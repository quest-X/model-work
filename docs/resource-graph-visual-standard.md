# Model Work Node 运维 Graph 视觉分类标准

本标准用于计算群运维 Graph。主画布只保留操作者直接关心的计算节点与传感器；网络、资源、Work Agent 和计算群归属仍保留在数据模型中，通过悬浮信息卡按需呈现。

## 1. 形状：表达实体类别

| 形状 | 实体类型 | 说明 |
| --- | --- | --- |
| 圆形 | 计算节点 | 表达可通过 model-work-node 管理、调度或建立 SSH 通路的主机。在线为绿色实线，离线为红色实线。 |
| 圆角矩形 | 传感器 | 表达摄像头和以后接入的其他物理传感器。传感器按归属关系排列在计算节点下方。 |

计算群、计算资源、Work Agent、SSH、公网出口与 Tailscale 都是内部数据实体，不在主画布上占用图形。以后新增实体时，只有“可直接管理的计算主机”归入圆形，只有“主机管理的物理感知设备”归入圆角矩形；其余信息进入悬浮信息卡或专门工作区。

## 2. 颜色：表达运行状态

| 颜色 | 含义 | 使用规则 |
| --- | --- | --- |
| 绿色 | 在线、健康、当前可用 | 节点在线或实体当前可调用。 |
| 红色 | 离线、故障、当前不可用 | 使用纯红色实线边框和红色状态点，不使用红色虚线。 |
| 琥珀色 | 传感器 | 摄像头、传感器等物理感知设备。 |

状态必须同时提供文字标签，颜色不能作为唯一的信息来源。

## 3. 线型：表达关系状态

| 线型 | 含义 |
| --- | --- |
| 实线 | 节点当前有效管理该传感器。 |
| 虚线 | 传感器仍在台账中，但管理关系当前不可用。虚线只用于连线，不用于实体边框。 |

主画布仅呈现“节点管理传感器”关系，使用琥珀色连线。其他关系留在后端图模型中，不直接显示。

## 4. 交互与可访问性

- 每个可见实体都必须暴露实体类型、形状和状态数据属性，供自动化测试和后续图谱工具读取。
- 在线/离线状态必须同时显示状态点、状态文字和最近心跳。
- 计算节点悬浮或键盘聚焦后，显示 SSH 通路、公网出口、Tailscale 私有组网、地址、最近心跳和当前可调用 agents。
- 传感器悬浮或键盘聚焦后，显示类型、型号、通道、接入方式、状态和归属节点。
- 悬浮信息卡不得遮挡当前实体，也不得拦截鼠标事件；移开鼠标或取消键盘聚焦后自动关闭。
